# Dataset Schema

## Purpose

This document defines what one dataset instance is in the thesis and what information must be stored for each graph.
The dataset is intended to support both heuristic baseline comparison and later GNN training/evaluation.

## What is one data instance?

One data instance is a graph together with a corresponding coloring produced by a heuristic method.
In this thesis, a data instance should also include the graph’s basic structural information and the result metadata needed for comparison and later learning.

## Data source

The primary data source is sparse matrices.
Each sparse matrix is interpreted through its sparsity pattern as an undirected graph, which is then used for coloring experiments.
SuiteSparse-style sparse matrix instances will be the main source of graph data for the thesis experiments.

## Graph representation

Each graph is stored as an undirected graph derived from the sparsity pattern of a sparse matrix.
At minimum, the stored graph representation should make it possible to recover the vertex set, the edge set, and the graph size information needed for experiments.
The representation should remain simple and consistent so that the same graph instance can later be used by heuristic methods and by the GNN pipeline.

## Heuristic coloring labels

For each graph, heuristic coloring results should be stored as labels generated by a baseline method such as ColPack.
At minimum, these labels should include the coloring assignment and the total number of colors used.
These heuristic coloring results serve both as baseline outputs for comparison and as target information for later learning experiments.

- coloring_assignment
- num_colors
- heuristic_method

## Metadata to store

For each graph instance, metadata should be stored to support reproducibility and comparison.
This should include at least the graph identifier, source name, graph size information, heuristic method name, and basic runtime/validity information.
This metadata is needed so that results can be traced back to the original graph instance and compared consistently across methods.

- graph_id
- source_type
- source_name
- num_vertices
- num_edges
- coloring_distance
- coloring_tool
- heuristic_method
- num_colors
- runtime
- valid

## Notes for future training

The stored dataset should later support supervised or structured learning with graph neural networks.
For this reason, the dataset should preserve information that can be used to relate each graph to its heuristic coloring output.

## Notes for future evaluation

The dataset should support evaluation on previously unseen graphs.
It should therefore be possible later to define graph-level train, validation, and test splits without changing the stored data format.
The main comparison metric will be the number of colors, while validity and runtime will serve as supporting evaluation information.
